## 1. 数据完整性与持久化

### 项目操作

- 合并到自身不再删除源项目。
- 移动或合并到不存在的项目时保持原数据，不再先移除源图片。
- 删除图片、移动图片、清除已完成图片时保留空项目及其元数据。
- 删除图片时保留未受影响项目的对象引用，减少无效增量保存。
- 批量添加标签同时过滤空标签、已有标签和输入中的大小写重复标签。

### 自动保存

- 保存任务串行执行；差异以最近成功保存的快照为基准计算。
- 使用版本号避免旧请求完成后错误显示新编辑“已保存”。
- 项目差异匹配由反复 `find/includes` 改为 Map/Set 查询。
- 加载失败时禁止进入编辑区，防止以空状态覆盖已有数据库；支持重新加载。
- 保存状态在页面可见，失败时提供重试按钮和备份提示。
- 存在未保存修改时注册离开页面提醒。浏览器可能限制此提醒，不能替代备份。
- 数据库打开失败后允许后续连接重试；遇到版本阻塞/连接终止时释放缓存连接。
- 异步初始化加入取消标记，避免 StrictMode 重复加载产生无效预览 URL。

## 2. 导入导出

- 修复重复文件输入共享同一个 ref 的问题：Sidebar 的旧输入没有实际导入回调，且随工作流变化可能引用错误节点。现在全应用使用一个常驻输入。
- ZIP 项目目录采用安全名称和不区分大小写的去重。
- 图片与对应标注名作为一组预留，避免同名图片以及 `photo.jpg` / `photo.png` 覆盖同一份 `photo.txt`。
- 处理路径分隔符、控制字符、Windows 保留名称、尾部点和空白。
- 单项目导出与 Worker 导出共用命名策略；图像原始内容不变。
- 补充 Worker 消息解码错误、发送失败、下载触发异常时的终止与错误传递；删除服务层的阻塞 alert。

## 3. 缩略图与搜索

- 缩略图缓存由全局字符串→Object URL Map 改为 File→Promise<Blob> 的 WeakMap。
- 相同文件实例复用生成任务，不再依靠文件名/大小/时间戳判断图片身份。
- 每个组件管理自己的 Object URL，在卸载/换图时释放；不释放调用者提供的 URL。
- 即使 Canvas 初始化失败，也通过 finally 关闭 ImageBitmap。
- 防止卸载后的异步失败创建无法释放的 fallback URL。
- 搜索词统一 trim/小写处理，支持 `len<6`、`len < 6`、`len > 10`、`status: error`。
- 用 useDeferredValue 降低大列表搜索对输入响应的影响；正则解析移出逐张过滤循环。

## 4. 安全

- 开发代理默认拒绝所有目标，只有 `.env.local` 明确列入 `TAG_MASTER_PROXY_ORIGINS` 的 HTTPS origin 才允许代理。
- 恢复上游 TLS 校验，禁用自动追踪重定向，并移除发送给上游的路由控制 Header。
- 保留开发环境代理回退，生产环境不尝试不存在的 Vite 代理。
- 使用 Headers API，保留 Headers 对象及元组数组中的 Authorization 等请求头。
- 被中止的请求不重试，HTTP 429 等响应不进入网络回退。
- 删除未使用的 `@google/genai` 依赖；在现有版本范围内修复依赖审计问题并更新锁文件。

**边界：**这仍是纯前端应用，API 密钥仍由浏览器端管理，并未改造成服务端密钥托管。代理 allowlist 必须由可信开发者配置，不应添加内部服务或不可信域名，也不要将开发服务器当作公开生产服务。审计“0 漏洞”仅代表本次 npm audit 的已知公告结果，不是绝对安全保证。

## 5. 交互与工程配置

- 保存/加载状态增加中、英、日文案。
- Toast 提供 status/alert 语义和关闭按钮标签；错误消息显示时间延长。
- 稳定 Toast 关闭回调，避免普通重渲染重置自动消失计时器。
- 添加键盘 focus-visible 样式，遵循 prefers-reduced-motion。
- 清理自动打开设置弹窗的定时器。
- React 与 i18n 独立分包，消除原先超过 500 KB 的单包警告。
- 新增 `test`、`test:watch`、`typecheck`、`check` 命令。
- 类型检查覆盖应用与 Vite 配置；补齐 Vite/Node 类型。
- 推荐 Node 22.12+；CI 使用 Node 22、npm ci、完整检查和生产依赖审计。
- Pages 发布构建也先通过检查；提供独立 PR CI。
- 增加 `.env.example` 及敏感环境文件、缓存文件忽略规则。

### Chromium 冒烟检查

在开发服务器上实际执行：

1. 页面加载，未捕获到 pageerror。
2. 上传 PNG 图片并保存到 IndexedDB。
3. 刷新页面，读取数据库验证图片记录仍存在。
4. 调用真实导出服务，经 Web Worker 生成并下载 ZIP。
5. 打开 ZIP 验证存在原始 PNG 条目。

这不是全工作流端到端覆盖：导出服务由浏览器脚本调用，未逐一点击所有导出弹窗选项。

### HTTP 检查

## 7. 运行方式

```bash
cd Tag-Master
# Node.js 22.12+
npm ci
npm run dev

# 全量检查
npm run check

# 构建与本地查看构建结果
npm run build
npm run preview -- --host 0.0.0.0
```

如果确需开发代理，将 `.env.example` 复制为 `.env.local`，只保留可信 API 的 HTTPS origin，然后重启。静态生产部署仍需要 API 的浏览器 CORS 支持。

## 8. 未覆盖与后续建议

- 未调用真实收费 AI API，没有验证用户自定义模型、服务商配额或网络连通性。

- 持久化仍以项目为单位保存图片 Blob；下一轮可评估项目元数据/图片记录拆表，降低超大项目写放大。
- 未完成 Safari/Firefox、移动端全布局和屏幕阅读器全站验证；本轮无障碍改进不等于完整 WCAG 审计。
- 未验证 PWA 离线升级与正在编辑数据的全部交互，需要独立生产环境测试。
- 浏览器数据仍可能因清理站点数据、隐私模式、磁盘压力丢失，应定期导出备份。
- 所有修改仍在工作区，建议 review diff 后自行提交、推送和发布。
